# Per-method retired-instruction counts, for ops.yml to report.
#
# `scripts/count-ops.sh check` gates the blessed rows in
# `scripts/expected-ops.txt`. This file is the open list: ops.yml measures every
# row here on every run and publishes the numbers, which is what turns a row in
# `scripts/method-counts.txt` from UNBLESSED into a number somebody can read and
# decide to bless.
#
# A row is measured in the test binary that holds its filter, and `count-ops.sh`
# confirms that before valgrind runs: profiling a binary where the filter matches
# no test runs zero tests, and then every symbol reads frame-less. The label says
# which of two different things happened.
#
#   Ir=inlined-not-a-frame  the test ran and the profile holds no frame for the
#                           symbol, so the method dissolved into its caller.
#   Ir=no-such-test         neither test binary has a test by the filter's name:
#                           the row drifted and needs re-pointing, not blessing.
#
# Until that check existed the harness profiled only the ferrox-app test binary,
# while 14 of these 31 rows name a test that lives in ferrox-core. Those blanks
# were never a verdict about inlining, so the `lto = "thin"` sentence published
# here for them was wrong and is gone; it stays a candidate explanation only for
# a row the fixed harness reports as `inlined-not-a-frame`.
#
# The first run through the fixed harness is read, not guessed: those 14 filters
# resolve, run their test, and still report `inlined-not-a-frame`. The test ran
# because the syscall table now shows the thread it spawns (`clone3`,
# `set_robust_list`, `futex`) where the app-binary run showed process startup and
# nothing else. So those leaves do dissolve into their callers in ferrox-core's
# own release test binary, and each such row must be re-pointed at the smallest
# caller that keeps a frame — or given the probe below — before it can carry a
# number.
#
# Renaming such a row to its test body is NOT the fix. A test frame charges the
# harness, the fixture bytes and any socket it opens, which is not a claim about
# the method; it converts an honest blank into a number that answers a different
# question. A dead row needs a probe whose cost is the method and nothing else —
# a repeated call over a fixed buffer — before it earns a number.
#
# One row has that now. `shadowsocks` points at
# `shadowsocks::tests::the_stream_cipher_costs_the_prga_loop_and_nothing_else`:
# 64 KiB of `Rc4::crypt` over one stack buffer, with one fold as the witness and
# no socket, allocation or fixture in the frame. Its number is the frame, so the
# fold and the frame entry ride inside it — which is why a probe row is read as
# the difference between two runs of the same row and never as the cost of the
# method alone. The in-memory half of this list is exact for the same reason:
# `masque::datagram_encode`, `ws::write_frame` and the masking probe held
# byte-identical across three runs, including one built with different debug
# info, while the two rows driven over a loopback socket moved between runs at
# the same flags.
#
# Five rows carry a number: `proxy::decode_trojan_request`, `foxy::read_frame`,
# `masque::datagram_encode`, `ws::write_frame`, and
# `ws::tests::mask_chunks_match_the_byte_loop`, whose body is the masking loop
# with no I/O, so the frame and the method are the same thing.
# The Trojan row's domain header carries `127.0.0.1`, so its frame is the parse
# and not the resolver, and the number it publishes reproduces.
#
